Проект представляет из себя быстрый способ воссоздать архитектуру состоящую из 2 серверов (локальный + удаленный) с определенными сервисами, которые решают специфические задачи. Проект сделан прежде всего для меня, а также для людей которые хотят свой готовый self-hosted сервер из коробки с полной системой обслуживания (см. ниже).

Также стоит уточнить что разместить всё на одном мощном VPS было бы проще, однако это потребовало бы слишком больших расходов на оплату такого сервера. Поэтому я выбрал гибридный подход: ресурсоёмкие сервисы работают на локальной машине, а удалённый VPS помогает организовать безопасный доступ к ним из интернета. Либо опять же, если хватает денег - можно спокойно арендовать сервера, вместо того чтобы держать их у себя дома.

# Краткий экскурс
## Основные сервисы
- **Nextcloud:** Облачное хранилище для файлов, контактов и фото.
- **Vaultwarden:** Легковесный менеджер паролей (совместим с Bitwarden API) для хранения шифрованных данных.
- **Homebox:** Учет вещей и оборудования
- **Gitea:** Легковесная система управления версиями на базе Git
- **Navidrome:** Стриминг личной музыкальной коллекции.
- **Audiobookshelf:** Сервер для аудиокниг и подкастов с синхронизацией прогресса.
- **Habitica:** Геймифицированный трекер привычек.
- **Actual Budget:** Личный бюджет с синхронизацией между устройствами.

## Сеть и безопасность
- **Webnames:** Регистратор доменных имён. Используется для владения доменом и управления DNS-записями (A-записи, Wildcard), необходимыми для работы SSL. (получение сертификатов происходит именно через Webnames, так как мой домен был куплен там, подробнее ниже)
- **WG-easy + AmneziaWG:** Зашифрованный туннель между устройствами и VPS, скрывающий инфраструктуру. Доступ к сервисам возможен строго из подсети VPN `10.8.0.0/24`; также имеется веб-панель для управления.
- **AdGuard Home:** Локальный DNS-сервер с функцией блокировки рекламы и трекеров.
- **Nginx:** Выполняет роль обратного прокси, блокируя любые внешние запросы, не принадлежащие внутренней сети туннеля.
- **SSH:** Настройка доступа по ключам `ed25519` с отключением входа по паролю.
- **Certbot:** Автоматизация получения SSL-сертификатов (Wildcard) через проверку DNS-01, интегрированную с API Webnames.
- **Fail2ban:** Защита от брутфорс-атак на системном уровне.

## Архитектура
- **Docker + Docker Compose:** Развертка всех приложений в контейнерах с помощью compose файлов.

## Мониторинг и контроль
- **Prometheus & Exporters:** Сбор метрик хоста (Node Exporter), контейнеров (cAdvisor) и самого веб-сервера (Nginx Exporter).
- **Grafana:** Визуализация состояния системы и производительности сервисов.
- **Blackbox Exporter:** HTTP(S)-проверки health-check локального сервера, Node Exporter и интерфейсов Grafana/Prometheus/Alertmanager; результаты собирает Prometheus.
- **Loki + Grafana Alloy:** Сбор логов со всех контейнеров в одно место.

## Алертинг и коммуникация
- **Alertmanager:** Маршрутизация уведомлений о критических событиях на Edge/VPS.
- **Prometheus + Alertmanager:** Алерты о недоступности проверяемых сервисов и приближении срока окончания TLS-сертификата.
- **TG Bot Integration:** Использование Telegram-бота для уведомлений от Alertmanager.

## Резервное копирование
- **BorgBackup + Borgmatic:** Зашифрованные резервные копии Workload и Edge с сжатием lz4.
- **rclone + Timeweb Cloud S3:** Автоматическая синхронизация локальных Borg-репозиториев в разные префиксы одного приватного бакета.
- **Восстановление:** Настройка, мониторинг и инструкции по восстановлению — в [docs/BACKUPS.md](docs/BACKUPS.md).

## Автоматизация
- **Ansible:** Система управления конфигурациями для автоматического развёртывания ОС, настройки безопасности и оркестрации Docker-контейнеров.
- **Установщик на Go и Wails:** удобный установщик, который сам развернет проект.
- **Vagrant:** Быстрое развертывание виртуальных машин для тестирования Ansible плейбуков.
- **Bash скрипты:** Автоматизация определенных шагов с помощью .sh скриптов.

## Удобство пользования
- **Homepage:** Красивая домашняя страница для удобства пользования сервисами в браузере.

# Actual Budget
Actual Budget входит в локальный стек Workload и доступен через Homepage по адресу `https://actual.<домен>/` (только через VPN). Приложение хранит состояние и файлы бюджета в `apps-data/actual-budget/`; этот каталог входит в существующие резервные копии `apps-data/`.

При первом открытии задайте пароль сервера Actual Budget. Для финансовых данных рекомендую дополнительно включить end-to-end encryption в настройках бюджета и сохранить пароль шифрования отдельно: его нельзя восстановить, если потерять. Инструкции: [официальный Docker guide](https://actualbudget.org/docs/install/docker/) и [руководство по шифрованию](https://actualbudget.org/docs/getting-started/sync/).

# Hermes Agent
Hermes Agent входит в стандартное развёртывание Edge/VPS и запускается в отдельном Docker-контейнере вместе с остальными Edge-сервисами. Отдельный третий сервер не нужен.

При настройке через установщик задаются OpenAI-compatible API Base URL, API-ключ и идентификатор модели. На первом запуске Ansible автоматически создаёт конфигурацию Hermes; API-ключ хранится в `apps-data/hermes/.env`, а настройки модели — в `apps-data/hermes/config.yaml`. Эти файлы не перезаписываются при повторном развёртывании, чтобы сохранялись изменения из Dashboard.

После развёртывания откройте карточку **Hermes Agent** на Homepage. Панель доступна по `https://hermes.<домен>/` только через VPN и HTTPS. Для входа используйте имя и пароль администратора, заданные в установщике.

Данные агента, история сессий, память и навыки хранятся в `apps-data/hermes/`. Для пользовательских файлов предусмотрена отдельная постоянная папка `apps-data/hermes-workspace/`, доступная агенту внутри контейнера как `/workspace`. Она автоматически создаётся при развёртывании и сохраняется между перезапусками. Ключи и файлы можно передавать в неё через SSH/SFTP под пользователем развёртывания; для приватных SSH-ключей выставляйте права `0600`. Всё содержимое этой папки доступно Hermes, поэтому кладите туда только те секреты, к которым вы готовы предоставить доступ агенту.
# Важная информация перед развертыванием проекта
1. **Поддерживаемая ОС:** Ubuntu 24.04 LTS.
2. **Настройка DNS:** В DNS-панели регистратора (например, на Webnames) необходимо направить A-запись основного домена и wildcard-запись (`*`) на внутренний IP-адрес Workload-сервера, где работает Nginx, — **`10.8.0.2`**. Это критически важно: весь трафик к вашим сервисам должен идти внутри защищённого туннеля AmneziaWG. Если направить домен на публичный IP-адрес сервера VPS, Nginx заблокирует внешние запросы из-за правила `deny all`.
3. **VPN для Vagrant:** HashiCorp в данный момент не работает в России, поэтому для запуска тестирования понадобится VPN. (После установки машин VPN следует выключить, либо можно включить split-tunneling на игнорирование диапазона `192.168.0.0/24`, так как иначе к тестовым виртуалкам не получится подключиться по SSH.)
4. **Сохранность бэкапов:** Храните `borgmatic_encryption_passphrase` отдельно от серверов и S3. Ветка `dev` автоматически синхронизирует зашифрованные репозитории в приватный S3-бакет; настройка, метрики и восстановление описаны в [docs/BACKUPS.md](docs/BACKUPS.md).
5. **Настройка wg-easy:** Если нет подключения к VPN, то можно попробовать зайти в интерфейс wg-easy и настроить параметры. (Подробнее можно прочитать в [AmneziaWG documentation](https://docs.amnezia.org/documentation/amnezia-wg).)
6. **Ошибки при выполнении Ansible плейбука:** Во время выполнения в самом начале могут появиться ошибки при подключении под root. Если скрипт при этом не завершился и развёртывание происходит на серверах, где уже есть пользователи, указанные в `secrets.yml`, — это нормально. В таком случае скрипт должен подключиться под созданными пользователями.
7. **Гарантия работы:** Работа проекта гарантируется только на полностью чистых серверах, либо если сервер уже был настроен с помощью этого проекта. В ином случае гарантии работы нет. Также не гарантируется работа при проблемах с подключением.
8. **Имя основного сетевого интерфейса WG-easy:** Если имя основного сетевого интерфейса на удаленном сервере не eth0, значит в WG-easy панели нужно поменять значение Device на реальное имя интерфейса сервера.

# Тестирование с Vagrant
1. Установите:
    - **[Vagrant](https://developer.hashicorp.com/vagrant/install)**
    - **[VirtualBox](https://www.virtualbox.org/wiki/Downloads)**
2. На основной системе в корне проекта выполните `vagrant up` для создания серверов для тестирования.
    - На вопрос **Which interface should the network bridge to?** нужно выбрать тот интерфейс, через который хост выходит в интернет.
3. При развертывании на сервера в secrets.yml пароль и имя пользователя должно быть `vagrant`
4. Чтобы остановить виртуальные машины, можно использовать `vagrant halt`.
5. Чтобы полностью удалить машины, можно использовать `vagrant destroy -f`.

# Сборка установщика из кода
## 1. Требования к окружению
Установите зависимости перед началом сборки:
- **[Go 1.27.3 (minimum Go version: 1.26.0; toolchain specified in go.mod)](https://go.dev/doc/install)**
- **[NPM (PNPM) / Node.js (15+)](https://docs.npmjs.com/downloading-and-installing-node-js-and-npm)**
- **[Wails v2](https://wails.io/docs/gettingstarted/installation)**
- **libwebkit2gtk-4.1-dev** — *только для Linux* (необходим для работы графического движка Wails)

## 2. Сборка стандартного бинарного файла
1. Зайдите в папку `/gui-installer`.
2. Выполните команду сборки под вашу ОС:
   - **Windows:** `wails build`
   - **Linux:** `wails build -tags webkit2_41`

Исполняемый файл `gui-installer` (или `gui-installer.exe`) будет сохранен в папке `gui-installer/build/bin/`.

## 3. Сборка .deb пакета (Linux)
1. Находясь в корне проекта, запустите bash-скрипт: 
```bash
./scripts/build_deb.sh
```

2. Установка собранного пакета:
```bash
sudo apt install ./gui-installer/build/bin/servehub-installer.deb
```

Готовый пакет servehub-installer.deb будет сохранен в папке gui-installer/build/bin/.
